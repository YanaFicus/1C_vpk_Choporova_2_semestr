# Практика 5. Интеграции в 1С

Внешние обработки (`.epf`) для демо-конфигурации **1С:Управление нашей фирмой (УНФ)**, редакция 3.0 (3.0.13.251), платформа 8.5.
Обработки выгружают и загружают данные через JSON и Excel, обмениваются данными между двумя базами и выполняют HTTP GET-запрос.

## Состав репозитория

| Файл | Задача | Описание |
|------|--------|----------|
| `ЭкспортНакладных.epf` | 1 | Выгрузка приходных накладных за период в JSON |
| `ИмпортРасходныхНакладных.epf` | 2 | Создание расходных накладных из JSON (без проведения) |
| `ОбменУНФ.epf` | 3 | Файловый обмен между базами «Головной офис» и «Филиал» |
| `ИмпортКонтрагентов.epf` | 4 | Загрузка контрагентов из Excel с проверкой дублей по ИНН |
| `HTTPЗапросGET.epf` | 5* | GET-запрос по введенному URL (проверка через Mockoon) |
| `incoming.json` | 1, 2 | Пример файла, полученного в задаче 1 |
| `contragents.xlsx` | 4 | Пример исходного Excel-файла с контрагентами |

> Задачи 1 и 2 работают в паре: файл, созданный первой обработкой, читает вторая.

## Описание обработок

### Задача 1. Выгрузка приходных накладных в JSON
- На форме задаются **начало периода**, **конец периода** и **путь к файлу**.
- Выгружаются документы «Приходная накладная» за период (без помеченных на удаление).
- Структура файла: массив объектов, у каждого поля `ДатаДокумента`, `Организация`, `Контрагент`, `Склад` и собственный массив `Товары` (`Номенклатура`, `Количество`, `Сумма`).
- Табличная часть читается из объекта каждого документа, поэтому товары разных накладных не смешиваются.

### Задача 2. Создание расходных накладных из JSON
- Кнопка **«Загрузить JSON»** читает файл, проверяет структуру и показывает число документов.
- Кнопка **«Создать накладные»** создает документы «Расходная накладная».
- Организация, контрагент, склад и номенклатура ищутся в базе **строго по наименованию**. Если элемент не найден или найдено несколько, выводится ошибка.
- Все ссылки проверяются **до создания первого документа**, поэтому при ошибке не создается ни одного документа.
- Номер присваивает платформа. Документы **записываются, но не проводятся**.

### Задача 3. Синхронизация двух баз УНФ
Реализован собственный файловый обмен в формате JSON. Одна и та же обработка открывается в обеих базах, роль выбирается на форме.

| Канал | Откуда → куда | Что передается |
|-------|---------------|----------------|
| `branch_to_head` | Филиал → Головной офис | Приходные накладные |
| `head_to_branch` | Головной офис → Филиал | Новая номенклатура |

- Каталог обмена: `C:\UNFExchange\<канал>\incoming | processed | error`. Подпапки создаются автоматически.
- **Защита от дублей:** объект в принимающей базе создается с тем же GUID, что и в источнике. Повторная обработка того же файла дублей не создает.
- Идентификаторы выгруженных объектов хранятся в общем хранилище настроек. Объект помечается выгруженным только после успешной записи файла.
- Файл записывается через временный `.tmp`, загрузка каждого файла выполняется в одной транзакции. Успешные файлы переносятся в `processed`, ошибочные в `error`.
- Автообмен: после нажатия **«Включить автообмен»** обмен выполняется каждые 30 секунд, пока обработка открыта.
- Журнал выводится на форме и пишется в `C:\UNFExchange\log_branch.txt` и `log_head.txt`.

### Задача 4. Загрузка контрагентов из Excel
- Файл: один лист, строка 1 заголовки, далее контрагенты. Столбцы: краткое наименование, полное наименование, вид контрагента, ИНН, КПП.
- Если контрагент с таким ИНН уже есть, выводится сообщение, новый элемент не создается.
- ИНН сравнивается **только по цифрам** (платформа хранит ИНН с пробелами, например «5 406 258 962»).
- Вид «Индивидуальный предприниматель» сопоставляется со значением «ФизическоеЛицо», так как в перечислении `ЮридическоеФизическоеЛицо` два значения.
- Итог (создано, дублей, пропущено или ошибок) выводится сообщением и в поле результата на форме.

### Задача 5*. HTTP GET-запрос
- В поле вводится полный URL, кнопка **«GET»** выполняет запрос и показывает код ответа и тело.
- Адрес разбирается на схему, хост, порт и путь. Поддерживаются `http` и `https`.
- Ошибки соединения выводятся текстом в поле ответа.

## Как пользоваться

### Требования
- Платформа 1С:Предприятие 8.5 (учебная версия подойдет).
- Демо-конфигурация УНФ. Для задач 1 и 2 в базе должны быть приходные накладные, организации, контрагенты, структурные единицы и номенклатура.
- Для задачи 3: две отдельные базы, созданные из одного шаблона (например, `UNF_Head` и `UNF_Branch`).
- Для задачи 5: программа [Mockoon](https://mockoon.com).
- Папки `C:\Exchange` (задачи 1, 2, 4) и `C:\UNFExchange` (задача 3) должны существовать и быть доступны для записи. Пути относятся к компьютеру, на котором выполняется серверный код (для файловой базы это ваш ПК).

### Запуск любой обработки
1. Запустите базу в режиме **«1С:Предприятие»**.
2. **Файл → Открыть…** (`Ctrl+O`) и выберите нужный `.epf`.
3. При предупреждении безопасности разрешите открытие (файлы собственные).

### Задачи 1 и 2
1. В `ЭкспортНакладных` укажите период (например, 01.10.2026 – 31.10.2026) и путь `C:\Exchange\incoming.json`, нажмите **«Выгрузить JSON»**.
2. В `ИмпортРасходныхНакладных` укажите тот же файл, нажмите **«Загрузить JSON»**, затем **«Создать накладные»**.
3. Проверьте список расходных накладных: новые документы с новыми номерами, не проведены.

> Повторный запуск «Создать накладные» создаст копии документов. Лишние можно пометить на удаление.

### Задача 3
1. Откройте `ОбменУНФ.epf` в **обеих** базах.
2. В `UNF_Branch` выберите роль **«Филиал»**, в `UNF_Head` роль **«Головной офис»**.
3. В каждой базе один раз нажмите **«Начальная фиксация»** (до создания тестовых данных), чтобы существующие демо-данные не передавались.
4. В обеих базах нажмите **«Включить автообмен»** и не закрывайте обработку.
5. В Филиале создайте приходные накладные, в Головном офисе новую номенклатуру. Примерно через минуту данные появятся в другой базе.
6. Для немедленного обмена используйте **«Выполнить обмен»**. Ход обмена виден в журнале.

### Задача 4
1. Закройте Excel-файл (иначе 1С не сможет его прочитать).
2. В `ИмпортКонтрагентов` укажите путь к файлу и нажмите **«Загрузить контрагентов»**.
3. Повторите загрузку: должны появиться сообщения о дублях по всем ИНН, новые элементы не создаются.

### Задача 5*
1. В Mockoon запустите окружение с маршрутом `GET /` (ответ `200`, тело `{"testmessage": "Hello world!"}`). Нажмите **«Start server»**.
2. В `HTTPЗапросGET` введите адрес (например, `http://localhost:3000/Test/`) и нажмите **«GET»**.
3. В поле ответа появится код 200 и JSON с `testmessage`.

## Отличия от методических материалов
- Заменены имена метаданных: в УНФ контрагент хранится в реквизите `Контрагент`, склад в `СтруктурнаяЕдиница`, табличная часть называется `Запасы`. Ключи JSON остались по заданию.
- Исправлены конструкции вида `Новый Файл(...).Существует()`: объект сначала присваивается переменной.
- Задача 2: универсальный строгий поиск по наименованию и предварительная проверка всех ссылок.
- Задача 3: защита от дублей по GUID вместо таблицы соответствий, журнал, транзакционная загрузка.
- Задача 4: нормализация ИНН, обработка ошибок записи.
- Задача 5: разбор произвольного URL, поддержка https, обработка ошибок.

## Технологии
- 1С:Предприятие 8.5, управляемые формы
- Язык запросов 1С, встроенный язык 1С
- JSON (`ЗаписьJSON`, `ЧтениеJSON`), `ТабличныйДокумент`, `HTTPСоединение`
- Внешние обработки (`.epf`), Mockoon

# Практика 4. Система компоновки данных (СКД) в 1С

Внешние отчеты (`.erf`) для демо-конфигурации **1С:Управление нашей фирмой (УНФ)**, платформа 8.5.
Данные берутся из регистров накопления «Запасы», «Продажи» и «Закупки».

## Состав репозитория

| Файл | Задача | Описание |
|------|--------|----------|
| `Задача 1 ОтчетАнализПродаж.erf` | 1 | Остатки и обороты номенклатуры по дням за произвольный период |
| `Задача 2 ОтчетПоОстаткаИОборотамПоДням.erf` | 2.1 – 2.3 | Остатки на начало и конец месяца, продажи за текущий и прошлый месяц, рекомендуемый объем закупки |
| `Задача 3 ОтчетПоОстаткаИОборотамПоДнямСРасшифровкой.erf` | 3 | Отчет из задачи 2 с расшифровкой по номенклатуре |
| `Задача 3 ОстаткиНаДату.erf` | 3 | Отчет с остатком выбранной номенклатуры на текущую дату (открывается расшифровкой) |

> Два отчета задачи 3 работают **только в паре**: расшифровка из первого открывает второй.

## Описание отчетов

### Задача 1. Остатки и обороты по дням
- Источник: `РегистрНакопления.Запасы.ОстаткиИОбороты` с периодичностью «День».
- В строках номенклатура, в колонках дни, в каждом дне четыре показателя: начальный остаток, приход, расход, конечный остаток.
- Пользовательские настройки: **начало периода**, **конец периода** (берется до конца дня), **отбор по номенклатуре** («В списке по иерархии»).

### Задача 2. Остатки, продажи и закупки за месяц
- **2.1.** Остатки номенклатуры на начало (01.<месяц> 00:00:00) и конец (последний день 23:59:59) выбранного месяца. Параметры: **Год** и **Месяц**.
- **2.2\*.** Колонки продаж за выбранный и за предыдущий месяц (`РегистрНакопления.Продажи.Обороты`).
- **2.3\*\*.** Колонки «Количество последней закупки» (регистр «Закупки») и «Рекомендуем закупить». Если продажи за текущий месяц выросли относительно прошлого, то рекомендуемый объем равен количеству последней закупки × 1,05. Иначе выводится «Расчет не требуется».

### Задача 3. Расшифровка
- В отчете из задачи 2 клик по названию номенклатуры открывает отчет **«ОстаткиНаДату»**.
- «ОстаткиНаДату» показывает остаток этой номенклатуры на **текущую дату** (в шапке видны параметр «Период» и «Отбор: Номенклатура Равно …»).

## Как пользоваться

### Требования
- Платформа 1С:Предприятие 8.5 (учебная версия подойдет).
- Демо-конфигурация УНФ с движениями по регистру «Запасы». Если движений нет, отчеты формируются корректно, но результат будет пустым.

### Запуск отчетов задач 1 и 2
1. Запустите демо-базу в режиме **Конфигуратор**.
2. Откройте файл: **Файл → Открыть…** и выберите нужный `.erf`.
3. Запустите отчет кнопкой **«Отладка → Начать отладку»** (F5) или кнопкой «1С:Предприятие».
4. В открывшемся отчете задайте параметры:
   - задача 1: начало и конец периода, при необходимости отбор по номенклатуре;
   - задача 2: **Год** и **Месяц**.
5. Нажмите **«Сформировать»**.

### Запуск задачи 3 (расшифровка)
Расшифровка находит второй отчет в справочнике «Дополнительные отчеты и обработки», поэтому его нужно один раз подключить:

1. В демо-базе откройте **Администрирование → Печатные формы, отчеты и обработки → Дополнительные отчеты и обработки** (в УНФ раздел может называться иначе, найдите справочник по названию).
2. Создайте элемент, нажмите **«Загрузить из файла»** и выберите `Задача 3 ОстаткиНаДату.erf`. Наименование элемента должно быть строго **`ОстаткиНаДату`**.
3. Убедитесь, что публикация отчета «Используется».
4. Откройте в Конфигураторе `Задача 3 ОтчетПоОстаткаИОборотамПоДнямСРасшифровкой.erf` и запустите его.
5. Задайте **Год** и **Месяц**, нажмите **«Сформировать»**.
6. **Кликните по названию номенклатуры.** Откроется «ОстаткиНаДату» с остатком этой номенклатуры на сегодня.

> Если у выбранной номенклатуры на текущую дату нет остатка, таблица будет пустой. Это не ошибка, попробуйте другую позицию (например, «ДСП»).
> В справочнике должен быть **один** элемент `ОстаткиНаДату`. После изменения отчета загружайте `.erf` заново, иначе откроется старая копия.

## Как устроена расшифровка

1. В форме первого отчета обработчик события `ОбработкаРасшифровки` по идентификатору расшифровки находит значение поля «Номенклатура» (если его нет в самом элементе, поиск идет по родителям).
2. Отчет `ОстаткиНаДату` ищется в справочнике по наименованию и подключается.
3. Открывается форма `ВнешнийОтчет.<Имя>.Форма.ФормаОтчета` с параметром `Номенклатура`.
4. Форма второго отчета сохраняет номенклатуру в реквизит отчета, а модуль отчета перед формированием задает параметр «Период» (текущая дата сеанса) и отбор «Номенклатура Равно …».

## Технологии
- 1С:Предприятие 8.5, система компоновки данных (СКД)
- Язык запросов 1С, встроенный язык 1С
- Внешние отчеты (`.erf`)
